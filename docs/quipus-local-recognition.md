# Quipus experimental local voice - 0.12.7 development candidate

> Experimental 0.12.8 DS-CNN trial is now authorized with a preserved 0.12.7 rollback. Its build flag is default OFF; target installation and labelled consent validation are pending. See [the separate experimental validation record](quipus-firmware-0.12.8-validation.md). The 0.12.7 observations below remain historical and do not establish consent reliability.

The new Waveshare ESP32-S3 profile keeps the existing local WakeNet **Computer** wake word. It adds the unmodified TensorFlow micro_speech evaluation classifier for the English words **yes** and **no**. The classifier has four outputs: silence, unknown, yes and no. It is not a speech transcriber and has no trained start-recording or status-report phrases. Offline menus therefore ask YES/NO questions; choosing start and granting recording consent must use separate fresh utterances. Online phrase recognition remains separate.

The recognizer's four labels are independent of the assistant's speaking voice.
Marin is prerecorded for local prompts and generated by the server for online
answers; it is not the YES/NO model. Neither the voice assets nor the SD card add
unrestricted local command transcription. [The offline pilot guide](quipus-offline-voice-pilot.md)
describes the two-stage intent/consent flow, encrypted saved-report cache and
online speech-service migration deadline. Acoustic acceptance remains pending;
this is not a custom Quipus wake-word model or a validated consent detector for
every accent or room.

## Resources and ownership

`quipus_local_recognizer_init()` initializes once from the application task. Before exposing availability, a startup integration test feeds both pinned public one-second YES/NO PCM fixtures, each padded into a five-second input, through the production frontend and classifier with the original strict numeric keyword thresholds. Both expected numeric labels and 41 windows must match. Environmental live-speech admission is separate: a padded public WAV is not a microphone/background calibration. Failure leaves local recognition unavailable. This tests target numerical integration, including ESP-NN; it does not test the microphone or user accents. The module never opens I2S, starts a task, or accesses networking. The application supplies existing signed 16-bit, 16 kHz mono microphone samples, between one and five seconds, and retains ownership of that buffer. Do not call inference from the realtime audio callback.

The official 18,800-byte classifier and its matching 8,772-byte audio-preprocessor model are embedded in flash. Their fixed 30 KiB and 16 KiB tensor arenas and a separate 1,960-byte rolling feature ring share a single aligned **49,064-byte PSRAM allocation**. The feature ring is separate because TensorFlow may reuse the input tensor storage after its last consumer. Resolver/interpreter storage is fixed. Inference reuses these allocations. Startup self-testing temporarily allocates another 160,000 bytes in PSRAM, reuses that buffer for both public fixtures, then clears and frees it. The two self-test PCM assets add 64,000 flash bytes; their source WAVs and hashes are recorded in `micro_speech_self_test.SOURCE.json`. The existing application capture buffer, WakeNet, audio, display, SD and networking need additional memory; 49,064 bytes is not a total firmware memory estimate. Other board profiles return unsupported and omit the embedded models.

The frontend processes 30 ms windows every 20 ms. A rolling 49-frame feature input supplies a one-second classifier window. Classification is evaluated every 100 ms and once at the last complete frame. A five-second input yields 41 evaluations. Each utterance resets the frontend noise estimate and features. All windows are examined before returning, so a late NO is not ignored after an earlier YES.

## Navigation is not recording consent

The candidate source now separates non-authorizing menus from strict consent.
`quipus_local_recognizer_classify_navigation()` selects a menu answer using the
same model, speech-supported keyword confidence and later-NO priority within
the captured response. It omits the consent-only environmental affirmative
vetoes. The existing `quipus_local_recognizer_classify()` remains strict by
default; its noise, activity and region rules are unchanged.

Each offline menu question is asked once. NO to the record choice may offer one
report question; unknown gives one unclear cue and returns to idle. There are
at most two distinct menu questions. Navigation uses the existing bounded
one-to-five-second early-silence capture, while recording consent always opens
a separate fresh full-five-second capture. A menu YES is erased and cannot
start recording by itself. This repairs the demonstrated menu retry path; it
is not evidence that offline acoustic consent is accepted or ready for pilots.

## Admission policy

Unknown, silence and failed inference never grant consent. After the candidate speech qualification below, two overlapping YES evaluations need a score of at least 200/255 and a margin of 32 over every other label. Any trusted NO wins; even a NO score of 128 blocks affirmative admission. A single YES spike is insufficient. A constant zero input returns silence, and a constant nonzero input returns unknown. The model scores and these prototype thresholds are not calibrated probabilities of correct consent.

This is an evaluation implementation. The stock example model must be tested with the actual Quipus microphone, Malaysian accents, distance, speaker playback and room noise before treating local consent as ready for pilots. A tiny keyword model can misclassify out-of-vocabulary speech; its unknown class does not prove absence of speech. Prompt playback must finish and a fresh response buffer must be captured to avoid recognizing the device's own voice. Full-phrase local recognition requires an independently trained and validated model; the SD card does not provide that model.

## Candidate speech-supported admission

The strict consent rules retained from 0.12.3 are described below. Navigation
explicitly uses its separate non-authorizing admission policy. Neither set of
rules establishes successful live recognition or a validated release.

A numeric target trace reproduces a concrete bug in whole-response voting: ten
speech-supported YES predictions were overridden by two NO predictions over the
quiet tail (RMS 18-19, zero VAD speech). That proves the voting failure path, not
that the human utterance was YES. The user tested YES/YES, NO/NO and YES/NO; the
individual trace is unlabeled. Its fixture is a numeric regression, not
human-label ground truth.

All five seconds and all 41 model windows remain inspected. Only contexts with actual VAD speech can vote YES, NO or possible-NO. A trusted speech-supported NO still wins. YES additionally requires a stable initial unvoiced noise prefix, no unexplained 20ms activity or DC drift, no truncated final speech, and independent attribution of every voiced region. Brief within-word gaps merge; each separated region must fit completely inside a trusted-YES context that overlaps no other region. Long or nonisolatable regions, or more than eight regions, return UNKNOWN. This prevents an earlier YES context from explaining a later undecoded refusal.

The activity backstop calibrates from100-500ms of the initial unvoiced prefix, reserving the final100ms before raw VAD onset so delayed detection cannot label the beginning of a word as room noise. Only a contiguous above-floor rise immediately adjoining that onset can join its region, for at most100ms; a quiet gap stops attachment. The entire expanded region must still fit an isolated trusted-YES context, while raw VAD support remains mandatory for word votes. Earlier, detached, late or otherwise unexplained activity still prevents affirmative admission. Calibration never uses later speech. The conservative prototype background ceiling is RMS96; the only actual target evidence so far was RMS19. Above-floor unexplained blocks, failed/unavailable VAD, missing calibration and a voiced final200ms prevent affirmative admission. Summary diagnostics record the first/last ambiguous block end time and RMS plus the number of attached onset frames; no per-frame PCM is logged. The final partial20ms block is included, with zero padding only for the VAD call and activity energy measured over the real samples. These limits can cause retries and do not prove that speech below the room noise was absent. No YES/NO model thresholds were lowered and no amplitude normalization was added.

## 0.13.2 room-noise and prompt-answer admission

A live offline session on board `80:45:6b:35:b7:dc` (2026-10-26, five consent
answers of "yes") scored YES 237-255 with no trusted or possible NO every time,
yet all five returned UNKNOWN. Two admission gates were the cause:

- **Prompt answers left no prefix.** Speech began within 100 ms of capture, so
  `background_rms=0` and the background was unverified. When the prefix has
  fewer than five blocks, calibration now uses the 25 blocks (500 ms) starting
  100 ms after the last voiced block. If any of those blocks is voiced or
  flagged, or there is not enough audio after the answer, the background stays
  unverified and YES is refused.
- **Single 20 ms room fluctuations.** Blocks at 29-33 RMS over a 17-18 floor
  (about 1.8x), including the decaying "s" 20 ms after VAD offset, were each
  treated as possible hidden speech. An above-floor block now counts only when
  it is part of a run of at least three contiguous blocks (60 ms, shorter than
  any syllable) or exceeds `3 x floor + 8`. DC drift still counts on any single
  block.

Unchanged: model thresholds (200/255 with a 32 margin, two YES windows), any
trusted NO or possible-NO veto, VAD-supported voting, isolated-region
attribution, the RMS 96 room ceiling, truncation and unexplained-speech checks.
The quiet late refusal fixture (100 ms at 1.8x floor, missed by VAD) and clicks
are still refused. This widens admission in real rooms; it is not acoustic
acceptance, which still requires the field tests below.

## Candidate integration and acoustic limitations

The 0.12.3 five-second menu trace at timestamp 103861 had eight trusted YES
windows, peak 255, no NO votes and all speech regions explained. One unvoiced
20 ms block at RMS 44 with background 27 (upper bound 43) caused UNKNOWN solely
through the strict environmental gate. Retrying then routed to a report choice,
without entering consent. This proves the menu-policy rejection path, not the
spoken label of every attempt or a self-wake loop.

The 0.12.4 navigation entry point keeps the model, raw-VAD-supported votes,
trusted NO precedence and possible-NO rejection, but omits consent-only
noise/activity/region affirmative vetoes. Each question has one early-silence
capture, at most five seconds; later NO priority applies within that captured
response. Consent still uses the default strict API and a fresh full five
seconds. RMS/confidence thresholds and model weights were not changed.

Navigation inputs shorter than 16,000 samples return UNKNOWN. A capture lasting
exactly one second by wall clock can be slightly short because of I2S/DMA block
alignment; that known boundary remains fail-closed and is not claimed repaired.

Bounded onset attachment addresses a plausible VAD delay, not an established
physical diagnosis. For strict consent, the reserved 100 ms plus the required
100 ms baseline means raw VAD onset earlier than 200 ms returns UNKNOWN. A
brief missed-VAD NO contiguous with later YES may be treated as onset activity;
isolated region containment cannot prove its word identity. Prompt-speed,
NO-then-YES and multiple-speaker trials remain required field tests.

## Acoustic diagnostics

During the current bench investigation, each evaluated window logs only its end time, RMS energy and four class scores in silence/unknown/yes/no order. The end time identifies an approximately 990 ms context, not the exact time a word occurred. The final summary includes capture peak/RMS/DC, exact clipping count, trusted YES/NO vote counts, first/last trusted NO context and peak class timing. ESP-SR WebRTC VAD uses one persistent mode-0 handle and a private 320-sample copy for 20 ms frames. Its bounded 250-byte speech mask provides voiced milliseconds per classifier context, total speech-frame count and last voiced time. Speech support now participates in admission, and VAD failure is explicitly marked unavailable rather than interpreted as silence. The reference host build supplies an explicit synthetic activity mask and makes no target-VAD accuracy claim. Injected-backend tests separately verify the exact target-window policy, late voiced and missed-VAD activity, ambiguous bursts, overlapping utterances, truncation, DC drift and VAD failure. No raw PCM or transcript is logged. Diagnostic logging itself does not authorize a decision; the candidate explicitly uses speech evidence in the admission gates described above. Returning NO is still a model classification, not proof a human declined.

An optional host-only `--native-model --characterize` sweep scales the public fixtures to 0.03, 0.1 and 0.3, applies DC offsets -1000/0/+1000, and shifts onset to 0/200/1000/4000 ms. Before speech-supported admission was added, in the initial72 artificial cases, all 36 NO cases returned NO; 27 YES cases returned YES and nine returned UNKNOWN due to the conservative possible-NO veto. No YES case returned NO. These observations do not establish field accuracy or justify automatic gain normalization. Real microphone test results take precedence.

## Reproducible checks

Local YES/NO navigation and online command recognition use bounded early-silence capture. Strict consent always uses a fresh full-five-second capture. A menu YES is erased before the new consent prompt and cannot authorize recording. `python scripts/test-firmware-offline-voice.py` executes the production controller for both SD and legacy admission, including separate policy calls, one question per menu choice, at most two distinct menu questions, and fresh consent after navigation.

Run `python scripts/test-firmware-local-recognizer.py` for the bounded production orchestration regression. It uses an injected inference backend and verifies model hashes, ownership, bounds, failure safety, silence/unknown, isolated YES rejection and late NO precedence. It does not measure model accuracy.

After resolving the managed IDF dependency, run `python scripts/test-firmware-local-recognizer.py --native-model` for a host build using the actual managed TensorFlow reference kernels, production inference adapter, both embedded models and pinned upstream YES/NO WAV fixtures. This compiles a host executable in `.tmp-local-recognizer/native`; it does not build or flash firmware. The first native build can take several minutes. The native test verifies both exact public fixtures through the startup numeric self-test, late NO precedence in both word orders, deterministic noise and a steady tone cannot grant consent, frontend reset, and optional `--unknown-pcm <16k-mono-s16.pcm>` playback clips. A real-model YES score with the synthetic host activity mask can still be conservatively rejected as UNKNOWN; the runner checks that numeric evidence without pretending the synthetic mask is target VAD. Official fixture success verifies numeric integration only; physical acoustic acceptance is still required. The current stock model labels a steady 1 kHz tone as NO, showing why correct negative keyword identification is not guaranteed despite the affirmative gate rejecting it.

The model commit, hashes and Apache-2.0 license are in `hardware/lantern-firmware/main/assets/micro_speech_yes_no.SOURCE.txt` and `micro_speech.APACHE-2.0.txt`. WAV fixture sources and checksums are in the host test's `fixtures/SOURCE.json`. Runtime dependencies are pinned to `espressif/esp-tflite-micro` 1.4.1 and its resolved `esp-nn` 1.4.1; existing ESP-SR stays at 2.0.1. No MultiNet engine is added.
